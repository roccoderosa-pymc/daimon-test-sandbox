# Baseline MMM (synthetic template)

> **Synthetic data.** Everything in this folder is generated by `generate_data.py`.
> Channel names, spend levels and effect sizes are choices made in that script,
> not estimates of real marketing performance. Use this as a working template,
> then swap in real data.

A small, end-to-end media mix model project on pymc-marketing 1.2.0:
synthetic data with known ground truth, a baseline `MMM`, a recovery check,
and an interactive budget notebook.

## Files

- `generate_data.py`: 156 weeks of weekly data, 6 channels (`tv`, `ctv`,
  `paid_search`, `paid_social`, `display`, `audio`), a `discount_rate` control,
  trend and yearly seasonality. Writes `data/synthetic_mmm_data.csv` and the true
  parameters to `data/ground_truth.json`.
- `fit_baseline.py`: fits the baseline MMM, writes `data/fit_summary.json`
  (diagnostics, in-sample fit, recovery against the truth),
  `data/posterior_draws.csv` (500 thinned draws) and `data/idata.nc`.
- `embed_payload.py`: embeds the posterior draws into the notebook (the
  `PAYLOAD = {}` line) so it runs with no data files. The committed notebook
  ships with an empty payload and asks you to run the pipeline first.
- `budget_explorer.py`: marimo notebook. Sliders set weekly spend per channel;
  it shows media-driven subscriptions with 94% intervals, cost per incremental
  subscription, response curves, an extrapolation warning, and a
  "reallocate the same total" optimiser with a max-change-per-channel limit.

Everything under `data/` is generated (seeded, so reruns reproduce it) and is
not committed.

## Run

```bash
pip install -r requirements.txt          # Python >= 3.12
python generate_data.py
python fit_baseline.py                   # about 2 minutes on 4 cores
python embed_payload.py
marimo edit budget_explorer.py           # or: marimo run budget_explorer.py
```

## Baseline model

```
new_subscriptions ~ intercept + gamma_trend * trend + gamma_disc * discount_rate
                    + yearly Fourier (2 modes)
                    + sum_c beta_c * logistic(lam_c * adstock_geom(spend_c / max(spend_c); alpha_c, l_max=8))
likelihood Normal, target and channels max-scaled by the library
```

Priors set in `fit_baseline.py` (all on the max-scaled target):

- intercept `Normal(0.5, 0.25)`
- `saturation_beta` `HalfNormal(0.3)` per channel
- `saturation_lam` `Gamma(alpha=4, beta=2)` (mean 2, sd 1)
- `adstock_alpha` library default `Beta(1, 3)`
- `gamma_control` `Normal(0, 1)`, `gamma_fourier` `Normal(0, 0.2)`
- noise `HalfNormal(0.1)`

A first fit with the library's default saturation priors (`beta ~ HalfNormal(2)`,
`lam ~ Gamma(3, 1)`), a Laplace Fourier prior and `target_accept=0.9` gave 47
divergences: the small always-on channels drifted into a beta-to-zero,
lam-to-large funnel. The priors above plus `target_accept=0.95` brought that to 2.

## Results on the synthetic data

- 4 chains x 1,000 draws: 2 divergences, max R-hat 1.005, min bulk ESS 1,780.
- In-sample R² 0.92, MAPE 2.1%.
- All six true channel totals fall inside their 94% posterior intervals.
- The always-on channels (`paid_social`, `display`) are under-estimated in the
  mean and have very wide intervals: with little week-to-week spend variation
  their effect is hard to separate from the intercept. This is what the design
  produces, and why experiments or lift tests matter most for always-on channels.

## Notebook maths

Adstock is normalised (weights sum to 1), so a constant weekly spend `x` has an
adstocked value of `x`. The notebook's long-run weekly contribution per channel is

```
beta_c * (1 - exp(-lam_c * x / scale_c)) / (1 + exp(-lam_c * x / scale_c)) * target_scale
```

evaluated per posterior draw. This forward pass reproduces pymc-marketing's
`channel_contribution` on the training data to machine precision.

## Next steps for a real-data version

- Replace the generator with your weekly extract; keep the same column contract.
- Put channel-specific priors on `saturation_beta` (e.g. from spend share or lift tests).
- Run a time-based holdout or rolling-origin backtest before trusting the curves.
- Calibrate with lift tests (`add_lift_test_measurements`) where experiments exist.
